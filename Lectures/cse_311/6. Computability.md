## 2026-05-20: DFAs, NFAs, and REs

Languages represented by DFAs, NFAs, or regular expressions are called **regular languages**.

We can convert from any RE to a NFA.
We can also convert from any NFA to a DFA.

## 2026-05-22: Limitations of DFAs and NFAs

### State minimisation algorithm

1. Put states into groups based on their outputs (whether they accept or reject).
2. Repeat the following until no change happens:
	- If there is a letter $s$ such that not all states in a group $G$ agree on which group $s$ leads to, split $G$ into smaller groups based on which group the states go to on $s$.
3. Finally, convert groups to states.

### CFGs aren't regular!

Suppose for contradiction that some DFA $M$ accepts $B$. We will show $M$ accepts or rejects a string it shouldn't.

Consider $S = {1, 01, 001, 0001, ...} = {0^n 1 : n >= 0}$.

Since there are finitely many states in $M$ and infinitely many strings in $S$, there exist strings $0^a 1 in S$ and $0^b 1 in S$ with $a != b$ that end in the same state of $M$.

Now, consider appending $0^a$ to both strings.

Since $0^a 1$ and $0^b 1$ end in the same state, ${} 0^a 1 0^a {}$ and $0^b 1 0^a$ also end in the same state, call it $q$. But then $M$ makes a mistake: $q$ needs to be an accept state since $0^a 1 0^a in B$, but $M$ would accept $0^b 1 0^a in.not B$, which is an error.

This proves that $M$ does not recognise $B$, contradicting our assumption that it does. Thus, no DFA recognises $B$.

## 2026-05-27: Cardinality and Computability

> **Cardinality**
> Two sets $A$ and $B$ have the same **cardinality** if there is a one-to-one correspondence between the elements of $A$ and those of $B$. More precisely, if there is a *1-1 and onto* function $f : A -> B$.

> **Countable**
> A set $S$ is **countable** iff it has the same cardinality as some subset of $NN$.

Equivalent: A set $S$ is countable iff there is an *onto* function $g : NN -> S$.
Equivalent: A set $S$ is countable iff we can order the elements $S = {x_0, x_1, x_2, ...}$

Rational numbers are countable via the [diagonal argument](https://en.wikipedia.org/wiki/Cantor%27s_diagonal_argument).

## 2026-05-29: The Halting Problem

`CODE(P)` means "the code of the program `P`".

> **The Halting Problem**
> Given:
> - `CODE(P)` for any program `P`
> - input `x`
>
> Output:
> - `true` if `P` halts on input `x`
> - `false` if `P` does not halt on input `x`

Turing proved that there is no program that solves the Halting Program.

```java
public static void D(String s) {
	if (H(s, s)) {
		while (true);
	} else {
		return;
	}
}

public static boolean H(String code, String x);
```

Assume `H` is a function that returns `true` if `code` halts on input `x`, and `false` if `code` does not halt.

Now we ask the question: Does `D(CODE(D))` halt?

### Proving problems undecidable

Our strategy is to perform the following reduction:

> "B decidable" $->$ "Halting problem decidable"

If we take the contrapositive,

> "Halting problem undecidable" $->$ "B undecidable"

Since we know the halting program is undecidable, it follows by MP that B is undecidable.
