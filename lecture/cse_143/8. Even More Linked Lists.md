Most of the time, it is easier to insert at the front of a linked list than at the back.

```java
// inserting a value at the front of a linked list
front = new ListNode(x, front);
```

```java
public LinkedIntList(int n) {
	front = null;
	for (int i = 0; i <= n; i++) {
		front = new ListNode(i, front);
	}
}

public void addSorted(int value) {
	if (front == null || value <= front.data) {
		front = new ListNode(value, front);
	} else {
		ListNode curr = front;
		while (curr.next != null && curr.next.data < value) {
			curr = curr.next;
		}
		
		curr.next = new ListNode(value, curr.next);
	}
}
```

To change a list, you either:
- Change `front`
- Change `node.next`

Short-circuits in binary logic: Always put the "robust" test before the "sensitive" test.

"Inchworm approach": Keep track of current and previous node, previous node advances before current node.

```java
public void addSorted(int value) {
	// handle other cases like above
	ListNode prev = front;
	ListNode curr = front.next;
	while (curr != null && curr.data < value) {
		prev = curr;
		curr = curr.next;
	}
	prev.next = new ListNode(value, prev.next);
}
```
