Up to now, two ways to change control flow (caused by changes in *program state*):
- Jumps
- `call` and `ret`

Processor also needs to react to changes in **system state**, e.g. `Ctrl-C` on the keyboard...

An **exception** is transfer of control to the operating system kernel in response to some **event**, i.e. change in processor state.

Once an exception occurs, we look at the **exception table** to know where to go next.

**Asynchronous exceptions**: Caused by events external to the processor. Examples:
- I/O interrupts (e.g. `Ctrl-C`)
- Timer interrupts: Every few milliseconds, an external timer chip triggers an input

**Synchronous exceptions**: Caused as a result of executing an instruction:
- Traps: Transfer control to OS to perform some function (e.g. system calls like opening a file)
- Faults: Unintentional but possibly recoverable
- Aborts: Unintentional and unrecoverable (e.g. hardware failures)

---

A **process** is an instance of a running program. As an abstraction, each process "thinks" it has control of all resources (registers, address space)!

Most of the time, multiple processes are running at the same time (**concurrently**) on a single device. The OS determines how to switch between processes.

---

Creating new processes:
1. `fork()`: Creates a spitting image of the parent process. (except for PID)
2. `exec*()`: Allows a process to do something else.
