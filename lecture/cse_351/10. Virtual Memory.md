## 2026-05-22

**Virtual address space**: A set of $N = 2^n$ virtual addresses.
- E.g. 64-bit virtual addresses can address several exabytes.

**Physical address space** is a set of $M = 2^m$ physical addresses.
- E.g. 8GiB main memory = 8.6E9 bytes.

1 virtual address space *per process*!

**Indirection**: The ability to reference something using a name, reference, or container instead of the value itself. A **flexible mapping** between a name and a thing allows changing the thing without notifying the holders of the name.

Examples:
- Domain Name Service (DNS)
- Call centres
- Dynamic Host Configuration Protocol (DHCP)

**Memory Management Unit (MMU)**: Sits between CPU and memory, converting from virtual addresses to physical addresses.

## 2026-05-27

The set of virtual pages that a program is "actively" accessing at any point in time is called its **working set**.
- If working set of one process <= physical memory, then good performance (after compulsory misses).
- If working set of all processes > physical memory, then performance meltdown due to **thrashing**.

### Address translation: Page tables

CPU-generated address can be split into:
`n-bit address: [ virtual page number | page offset ]`
- Use lookup table that we call the **page table (PT)**.
- Replace VPN with PPN to generate physical address.
- Each process has its own page table for lookup.
- A register for this! `PTBR` (Page table base register) stores where this page table starts in memory.

Physical memory is essentially a direct-mapped cache!

## 2026-05-29

MMU has to access memory *twice*: Once to get the PTE for translation, and then again for the actual memory request.

**Translation Lookaside Buffer (TLB)**: Small hardware cache in MMU that maps VPNs to PPNs.
- (Potentially) Eliminates one memory access!

Fetching data on a memory read:
1. Address translation (check TLB)
	- TLB hit: Fetch translation, return PPN
	- TLB miss:
		- Page table hit: Load page table entry into TLB
		- Page fault: Fetch page from memory, update corresponding PTE, then load into TLB
2. Fetch data: Cache hit/miss as discussed previously

### Context switching revisited

What needs to happen when the CPU switches processes?
- Registers:
	- Save state of old process, load state of new process
	- Including Page Table Base Register (PTBR)
- Memory:
	- Nothing to do! Pages for processes already exist in memory/disk and are protected from each other
- TLB:
	- *Invalidate* all entries in TLB - mapping is for old process' VAs
- Cache:
	- Can leave alone because storing based on PAs
