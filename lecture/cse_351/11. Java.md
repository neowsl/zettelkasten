## 2026-06-01

Data in Java:
- Pointers are called references in Java
- Java's portability-guarantee fixes the sizes of all types (e.g. `int` will always be 4 bytes, regardless of machine)
- No unsigned types to avoid conversion pitfalls.
- `null` is typically represented as 0 but "you can't tell"

Arrays in Java:
- Every element initialised to 0 or `null`
- Length specified in immutable field at start of array (accessed via `array.length`)
- Every access triggers a bounds-check

Strings in Java
- Two-byte Unicode instead of ASCII
- String not bounded by a `\0` (instead stored as hidden length field)
- All String objects read-only

Classes in Java
- Similar to structs in C
- References mean less spatial locality

References in C
- References in Java can only point to *the starts of* objects

## 2026-06-03

**Virtual method table (vtable)**: A jump table for instance ("virtual") methods plus other class info.
- Only one table per class
- Each object instance contains a **vtable pointer**

Inheritance simply just "tacks on" new code in subclass into superclass.

### Implementing programming languages

Many choices in programming model implementation...
- Can either compile or interpret

**Interpreters** have a long history and are still in use.
- E.g. Lisp, Python, JavaScript, Ruby, etc.

Interpreters "gobble code" like Pac-Man, usually run slower than compiled binaries, but are more portable.

Java first compiles a program via `javac` into a `.class` file, then interprets it using the JVM.

## 2026-06-05

Java bytecodes:
- "Assembly code" for the JVM
	- Works on all JVMs!
	- Hardware-independent!
- Bytecodes are typed (unlike x86 assembly)

```java
iload 1
iload 2
iadd

istore 3
```

- All values stored on stack, works like a stack calculator
